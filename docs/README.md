# OctoAcme Project Management Docs

This directory contains OctoAcme's project management processes, role guidance, and delivery practices. Use this README as the starting point for understanding how projects move from idea through delivery, release, and continuous improvement.

## Project management process overview

OctoAcme uses a structured lifecycle of initiation, planning, execution, release, and retrospective. Initiation validates the business need, identifies stakeholders, defines measurable success criteria, and establishes an initial timeline, risks, and resource needs. After approval, planning turns the initiative into a prioritized backlog of shippable increments with acceptance criteria, estimates, dependencies, milestones, a release plan, and a shared Definition of Done.

During execution, teams use a project board to move work from Backlog through Ready, In Progress, In Review, QA, and Done. The process emphasizes small pull requests, issue-linked acceptance criteria, automated tests and linting, security scanning, code review, and manual QA where appropriate. Releases require passing acceptance criteria and CI checks, release notes, a rollback or mitigation plan, and staging smoke tests before production verification. Risks and dependencies are recorded, owned, reviewed regularly, and escalated from the team to the Project Manager, Product Lead, and Sponsor when needed.

Project Managers coordinate schedules, risks, dependencies, meetings, documentation, and stakeholder communications. Product Managers define outcomes, prioritize the roadmap and backlog, and measure customer and business value. Developers implement and test the solution, participate in planning and reviews, and identify technical risks. Communication includes standups, weekly delivery and PM/Product Manager syncs, milestone demos, stakeholder updates, and a single source of truth for status. After each sprint, release, milestone, or incident, retrospectives capture lessons and turn the highest-priority improvements into owned backlog items with due dates and success criteria.
